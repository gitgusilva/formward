# Contributing to this fork

This repository is a **fork** of [vee-validate](https://github.com/baianat/vee-validate) (v2.2.x), adapted for Vue 3. The original project is maintained by [Baianat](https://github.com/baianat).

To contribute to the **original** (Vue 2) project, use the upstream repository:  
https://github.com/baianat/vee-validate

---

Below is what you need to know to contribute to this fork.

### Getting started

Clone the fork and install dependencies:

```bash
git clone <your-fork-url>
cd vee-validate-2.2.15
npm install
```

### Folder structure

- **src** — Source code
  - **core** — Validator core, ErrorBag, Field, etc.
  - **rules** — Validation rules
  - **utils** — Utility functions
- **dist** — Build output (UMD, ESM, locales), generated by `npm run build`
- **docs** — Documentation (Markdown)
- **scripts** — Build and locale generation scripts

### Code style

Style is enforced with ESLint. Violations may block merging.

### Build

```bash
npm run build
```

Produces UMD, ESM, and locale files in `dist/`.

### Tests

Tests use **Vitest** (Vite-native runner). Project skills in `.agents/skills/` (vitest, vue-testing-best-practices) define the testing patterns: use `vi` for mocks (global from `tests/setup.js`), `await flushPromises()` for async, and avoid snapshot-only assertions. Run:

```bash
npm test          # watch mode
npm run test:run  # single run
npm run cover     # coverage
```

**TypeScript:** These modules are in TypeScript: `src/config.ts`, `src/state.ts`, `src/eventBus.ts`, `src/modes.ts`, `src/core/ruleContainer.ts`. The rest is Flow-typed `.js`. Run `npm run typecheck`; add `.ts` or `*.d.ts` under `src/` for incremental migration. Project skill: `.agents/skills/typescript-advanced-types`.

**Excluded tests:** Some unit and all integration tests use Vue 2 Test Utils API (`createLocalVue`, etc.) and are excluded from the default run until migrated to Vue 3. Excluded: `tests/unit/component.js`, `directive.js`, `mixin.js`, `validator.js`, `validatorDecorator.js`, `resolver.js`, `localization/i18n.js`, `i18nDrivers.js`, and `tests/integration/**`.

### Pull requests

- Use a clear title.
- Keep the PR up to date with the target branch.
- Use the `[WIP]` prefix for work-in-progress PRs if needed.
